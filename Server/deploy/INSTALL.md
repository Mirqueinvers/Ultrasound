# Установка сервера Ultrasound на Windows (без Docker)

> Пакет развёртывания на **чистый Windows-ПК** без Docker.
> Сервер состоит из двух служб Windows: **PostgreSQL 16** (база данных) и **Ultrasound API** (Node.js, порт 4000).
> Обе стартуют автоматически при включении компьютера — даже без входа в Windows.

---

## Шаг 0. Что понадобится

- Серверный ПК (Windows 10/11, 64-бит, 4 ГБ ОЗУ, ~5 ГБ свободного места).
- Папка `Server/` (этот проект), скопированная на серверный ПК, например в `C:\Ultrasound\Server`.
- Интернет на серверном ПК (для установки PostgreSQL, Node.js и зависимостей npm).

> **Важно:** путь к папке не должен содержать русских букв и пробелов — используйте `C:\Ultrasound\Server`.

---

## Шаг 1. Установить PostgreSQL 16

1. Скачать установщик: https://www.postgresql.org/download/windows/ (версия **16**).
2. Запустить установку, в мастере:
   - **Запомнить пароль суперпользователя `postgres`** (понадобится скрипту);
   - порт оставить **5432**;
   - **не менять** настройку «Install as a service» (служба Windows с автозапуском).
3. Дождаться завершения установки.

Проверка: в меню «Пуск» появится «pgAdmin» / «SQL Shell (psql)».

---

## Шаг 2. Установить Node.js 22 LTS

1. Скачать: https://nodejs.org (версия **22 LTS**).
2. Установить `.msi` со всеми настройками по умолчанию.

Проверка: открыть командную строку и выполнить `node --version` — должна вывестись версия.

---

## Шаг 3. Скопировать проект `Server/`

Скопировать папку `Server/` с машины разработки на серверный ПК в `C:\Ultrasound\Server`.

**Скопировать обязательно:** папки `src/`, `prisma/`, файлы `package.json`, `package-lock.json`, `tsconfig.json`, `.env.example` и папку `deploy/`.

**Можно не копировать:** `node_modules/`, `dist/`, `.env`, `Dockerfile`, `docker-compose.yml`, `tests/`.

---

## Шаг 4. Запустить установку

1. Открыть папку `C:\Ultrasound\Server\deploy`.
2. **Правой кнопкой мыши** по `install-server.bat` → **«Запуск от имени администратора»**.
3. Ответить на вопросы скрипта:
   - **Пароль для пользователя БД `ultrasound`** — придумайте свой (только латиница/цифры);
   - **Пароль postgres** — тот, что вы задали при установке PostgreSQL (Шаг 1).

Скрипт автоматически:
1. создаст файл `.env` (сам сгенерирует секрет `JWT_SECRET`);
2. создаст пользователя `ultrasound` и базу `ultrasound` в PostgreSQL;
3. установит зависимости (`npm ci`);
4. применит миграции Prisma (создаст таблицы);
5. соберёт сервер (`npm run build`);
6. скачает и установит **NSSM** — зарегистрирует службу **`UltrasoundAPI`** с автозапуском;
7. запустит службу;
8. откроет порт **4000** в брандмауэре Windows;
9. проверит работу API и покажет IP-адреса компьютера.

В конце должно появиться:
```
============================================================
  УСТАНОВКА ЗАВЕРШЕНА
============================================================
  Health:     http://localhost:4000/api/health
```

---

## Шаг 5. Проверить сервер

С этого же ПК открыть в браузере:
```
http://localhost:4000/api/health
```
Должно отобразиться `{"status":"ok"}`.

С **другого** компьютера в локальной сети открыть:
```
http://<IP-сервера>:4000/api/health
```
(IP-адрес сервера показал скрипт на последнем шаге, либо `ipconfig` → IPv4).

---

## Шаг 6. Настроить клиентов

**Desktop** (на каждом кабинете):
- на экране «Адрес сервера» ввести: `http://<IP-сервера>:4000`

**Registry** (регистратура) — задать переменные окружения:
- `CENTRAL_API_URL` = `http://<IP-сервера>:4000/api`
- `REGISTRY_USERNAME` = `registry`
- `REGISTRY_PASSWORD` = `registry123` (при необходимости создайте свою учётку на сервере)

---

## Шаг 7. Миграция данных Desktop (выполняется один раз)

### Простой способ (один файл)
Положить `ultrasound.db` на серверный ПК в папку `C:\ultrasound\ultrasound.db` и запустить
от администратора `deploy\migrate-data.bat`. Скрипт сам:
- сделает резервную копию `ultrasound.db` рядом с файлом;
- установит зависимости (если нужно);
- запустит миграцию и покажет сводку (пользователи, пациенты, исследования).

### Вручную (несколько баз)
```bat
cd C:\Ultrasound\Server
npx tsx prisma/migrate-local-dbs.ts --from "C:\путь\к\ultrasound.db" --to "postgresql://ultrasound:<пароль>@localhost:5432/ultrasound"
```
`--from` можно указывать несколько раз (по одному файлу на кабинет).

> ⚠️ **Скрипт миграции запускается ОДИН раз.** Повторный запуск создаст дубли
> пациентов и исследований. Если нужно перезапустить — сначала очистите таблицы:
> `TRUNCATE print_block_overrides, research_studies, researches, patients, medison_mappings CASCADE;`

---

## Шаг 8. Миграция данных Registry (регистратура)

> В базовой архитектуре данные старой регистратуры (`registry.db`) не переносились —
> новая БД стартовала пустой. Этот шаг переносит пациентов, врачей и записи
> на приём из старого `registry.db` (опционально).

### Простой способ (один файл)
Положить `registry.db` на серверный ПК в папку `C:\ultrasound\registry.db` и запустить
от администратора `deploy\migrate-registry-data.bat`. Скрипт сам:
- сделает резервную копию `registry.db` рядом с файлом;
- установит зависимости (если нужно);
- запустит миграцию и покажет сводку (пациенты, врачи, записи на приём).

### Вручную
```bat
cd C:\Ultrasound\Server
npx tsx prisma/migrate-registry-db.ts --from "C:\ultrasound\registry.db" --to "postgresql://ultrasound:<пароль>@localhost:5432/ultrasound"
```

Скрипт **безопасен при повторном запуске** — дубли не создаются (врачи и записи
проверяются на совпадение). Если нужно полностью очистить только данные регистратуры:
`TRUNCATE appointments, doctors CASCADE;` (пациентов трогать не нужно — они общие
с Desktop).

> Пациенты из `registry.db` объединяются с пациентами Desktop по (ФИО, дата рождения):
> если такой пациент уже есть в базе (например, после миграции `ultrasound.db`),
> записи на приём привяжутся к нему, без дублей. Тот же механизм работает в обратном
> порядке — при миграции Desktop скрипт учитывает уже загруженных пациентов
> регистратуры.

## Обновление сервера

### Быстрый способ — по локальной сети (веб-деплой)

Устанавливается один раз, дальше обновление с любого ПК в сети без доступа к серверному ПК:

1. **Один раз** скопируйте на серверный ПК обновлённые `src/`, `prisma/`,
   `package.json`, `package-lock.json`, `tsconfig.json` и папку `deploy/`
   (в ней появились `deploy-runner.cmd` и `deploy-lan.bat`), затем запустите
   `deploy\update-server.bat` от администратора.
2. Убедитесь, что в `C:\Ultrasound\Server\.env` есть `DEPLOY_TOKEN`
   (его генерирует `install-server.bat` при установке; при ручной замене `.env`
   сгенерируйте токен сами — любая длинная случайная строка).
3. На рабочем ПК откройте папку `Server\deploy` и выполните:
   ```
   deploy-lan.bat <IP-сервера> <DEPLOY_TOKEN>
   ```
   Скрипт соберёт пакет из `src/`, `prisma/`, `package.json`, `package-lock.json`,
   `tsconfig.json` и отправит его на сервер. Ход обновления:
   `http://<IP-сервера>:4000/deploy` (там же веб-страница с выбором файла и лог).

Что делает сервер при обновлении: обновление выполняется **в два этапа**
(`deploy\deploy-runner.cmd`):
- **Фаза 1** — пакет распаковывается в `deploy\staging`, там выполняются
  `npm ci`, `prisma generate` и сборка. В это время работающая служба
  **продолжает обслуживать запросы** — если что-то пойдёт не так, сервер не ляжет.
- **Фаза 2** — короткое переключение: остановка службы, резервная копия
  в `C:\Ultrasound\Server\backups\`, подстановка новых файлов и `node_modules`,
  миграции Prisma, запуск службы и **проверка `/api/health`** (до 90 сек).
  При любой ошибке — автоматический откат к предыдущей версии и запуск службы.

Лог: `C:\Ultrasound\Server\logs\deploy.log`. Если обновление было прервано
(например, перезагрузкой ПК) и сервер не поднялся — рядом с пакетом останется
маркер `C:\Ultrasound\Server\deploy\update-in-progress.txt`, а в
`C:\Ultrasound\Server\backups\` и `node_modules.old` — всё для ручного
восстановления.

> **Важно:** пакет веб-деплоя содержит только `src/`, `prisma/`, `package.json`,
> `package-lock.json`, `tsconfig.json`. Файлы из папки `deploy/`
> (в т.ч. обновлённый `deploy-runner.cmd`) в него **не входят** — после правок
> в `deploy/` копируйте их на сервер вручную (общая папка/флешка).

> Безопасность: `DEPLOY_TOKEN` нужен для отправки пакета — держите его в секрете.
> Порт 4000 уже открыт для клиентов, поэтому не публикуйте токен наружу.

### Запасной способ — вручную

Заменить в `C:\Ultrasound\Server` файлы `src/`, `prisma/`, `package.json`,
`package-lock.json`, `tsconfig.json` на новые, затем запустить
`deploy\update-server.bat` от администратора. Он пересоберёт и перезапустит службу.

## Удаление сервера

`deploy\uninstall-server.bat` (от администратора) — остановит и удалит службу API. PostgreSQL останется (можно удалить через «Установка и удаление программ»).

---

## Возможные проблемы

| Симптом | Решение |
|---|---|
| «Node.js не установлен» | Установить Node.js 22 LTS (Шаг 2) и перезапустить скрипт |
| «PostgreSQL не найден» | Установить PostgreSQL 16 (Шаг 1); скрипт ищет `C:\Program Files\PostgreSQL\*\bin\psql.exe` |
| «Не удалось создать пользователя» | Неверный пароль `postgres`, либо служба PostgreSQL не запущена (проверьте в «Службы») |
| API не отвечает после установки | Смотреть лог: `C:\Ultrasound\Server\logs\api-error.log` |
| Другие ПК не подключаются | Порт 4000 заблокирован брандмауэром — правило должно было создаться автоматически; проверьте или добавьте вручную |
| Окно скрипта мгновенно закрывается | Запускайте скрипт через ПКМ → «Запуск от имени администратора» (не двойным кликом). Если файл `.bat` редактировали на Linux/Mac — пересохраните его с Windows-переводами строк (CRLF) |
| Сборка падает: «Namespace Prisma has no exported member…» | Prisma Client не сгенерирован. В текущей версии скрипта это делает `npx prisma generate` (шаг после миграций) — обновите скрипт из `Server_deploy.zip`. Для ручной починки: в папке сервера выполните `npx prisma generate`, затем `npm run build` |
| Служба не запускается после перезагрузки ПК | Проверить, что обе службы в «Службы» (services.msc): `postgresql-x64-16` и `Ultrasound API Server` — тип запуска «Автоматически» |
| После обновления служба не запускается | Смотреть `logs\deploy.log` и `logs\api-error.log`. Если остался маркер `deploy\update-in-progress.txt` — обновление было прервано. Восстановление: в `C:\Ultrasound\Server` выполнить `npm ci`, `npx prisma generate`, `npm run build`, затем `nssm start UltrasoundAPI` |
